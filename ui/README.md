# ui/

The web pages. Plain HTML, CSS and JavaScript. No build step. FastAPI serves this folder at `/`, and tells the browser to re-check the files each time, so an update shows up at once. The look is the "neo-arcade" design: warm cream surfaces, black outlines, hard offset shadows, and the Space Grotesk, Plus Jakarta Sans and Space Mono fonts (loaded from Google Fonts, as are the Material Symbols icons).

- `index.html` + `landing.css` + `landing.js` + `flow.js` - the landing page at `/`: a retro collage on blue felt, with torn-paper section edges and floating stickers. The felt and paper textures and the tears are drawn in code (SVG noise and displacement filters, defined at the top of `index.html`), so each tear takes the exact colour of its section and no tear image is needed. It opens with a headline, one "Open the Chat" button and a small retro window that types an example question and shows how it is answered (it cycles through three example paths: company documents, web search, fallback; these are fixed example texts, not live calls). Below that it explains the agent flow, the knowledge base and the safety rules, with a "Decision Path Viewer" (▲ ▼) you can step through yourself. The only link to the vault (staff tools) is a small, quiet "IT staff: manage documents" link in the footer.
- `flow.js` draws the "How a question travels" window in the knowledge-base section: an animated map of the agent's real graph (`app/agent/graph.py`) with four routes to pick from (company answer, web fallback, not confirmed, just chat). A glowing packet follows the real routes, nodes light up as it arrives, the grader shows a GOOD or WEAK verdict, and a caption names the function and the model (fast, answer, or none) used at each step. The route texts are written by hand from what the graph does, so if `graph.py` changes, update the routes in `flow.js` too. It uses no library, animates only transform and opacity, pauses when the section is off screen or the tab is hidden, and with "reduce motion" switched on it shows the whole route lit at once with every step written out.
- `chat.html` + `app.js` - the chat workspace: a sidebar of recent chats, a "new chat" view with suggested questions, and an active thread with the answer, its source cards and the decision path.
- `vault.html` + `vault.js` - the Knowledge Vault: drag and drop upload, a progress strip, and a searchable, filterable list of what was uploaded from this browser.
- `settings.html` + `settings.js` - the staff key, a live service check, and the recent-questions log.
- `common.js` - helpers used by all three pages (server calls, admin key, saved lists).
- `style.css` - the design for the chat, vault and settings pages (the landing page has its own `landing.css`). Works on phones too.
- `assets/` - the sticker images.

What the pages do:

- Chat calls `/api/chat`. While a question runs, the send buttons ignore clicks (so one question is never sent twice) and a screen reader hears "Thinking…" and then which source answered. Web sources are links. Company documents show their title and file name. The "Decision Path" chip shows or hides the steps under each answer.
- Chats are saved in this browser only (`localStorage`). Each question is sent with the last few earlier questions and answers of the same chat (never a failed reply, never another chat), so a follow-up works. The server stores nothing: it reads them for that one answer.
- The vault uploads through `/api/ingest` and needs the admin key. The key is kept in this tab's session storage only. The server has no "list documents" endpoint, so the list is this browser's own upload history, and "Remove" only edits that list: it never deletes anything from the knowledge base.
- Settings reads `/api/health` and `/api/audit`. If `ADMIN_API_KEY` is not set on the server, it says the staff tools are switched off.
- Text from answers, sources and the audit log is added with `textContent`, never `innerHTML`, so web text cannot inject HTML.
